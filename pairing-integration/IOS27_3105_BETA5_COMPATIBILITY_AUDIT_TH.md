## ความสามารถที่ปรากฏจากสัญลักษณ์และสตริง
พบข้อความเกี่ยวกับ AirLift, Remote Pairing, multihost tunnel, RSD, ATC, FileService, การอ่าน/เขียน และ diagnostic round trip. การมีโค้ดไม่ได้เท่ากับใช้สำเร็จบน iOS ทุกรุ่น; FileService หรือฟีเจอร์บางตัวอาจไม่พร้อมใช้งานแม้ Pairing ผ่าน

มีข้อความว่า `Only supported offset for iOS/iPadOS 17.0 - 26.0.x` จึงต้องแยกระบบ kernel/offset แบบเดิมจากเส้นทาง AirLift; อย่านำผลสำเร็จของ AirLift ไปอ้างว่า kernel exploit รองรับ 27.x

## เทียบกับ RUIZEN CLIENT Build 11
RUIZEN Build 11 (repo `Iowzaza225/3105`) ใช้ `RUIZEN_CLIENT_BUILD10.zip` เป็นซอร์ส ตั้งค่า identity, icon และ `CFBundleVersion = 11` ใน GitHub Actions. ระบบ pairing ที่เพิ่มใน branch นี้ยังไม่ได้พิสูจน์ RSD/ATC/FileService หรือสิทธิ์เขียนไฟล์บน iOS 27.0.1.

ซอร์ส `ExploitSupportPolicy` ที่ตรวจได้ใน ZIP RUIZEN เดิมจำกัด `isSupported` ให้ iOS 27.0.0 และ 4 Beta Build ดังนั้น iOS 27.0.1 จึงถูกปฏิเสธโดยเงื่อนไขเดิม แม้ AirLift จะสามารถเป็นอีกเส้นทางหนึ่งได้. ไม่ควรแก้ให้ `isSupported = true` กว้าง ๆ โดยไม่มีผลตรวจความสามารถจริง.

## แผน QA ที่แนะนำ (ไม่แตะ kernel exploit)
1. ตรวจ Build จริงใน Settings > General > About ไม่ใช่ดูแค่เลขเวอร์ชันทางการตลาด
2. บันทึกแยก Pairing-created, Pair-Verify, RSD-connected, ATC-available และ read/write/read-back เฉพาะไฟล์ทดสอบที่ได้รับอนุญาต
3. เก็บรายงานที่ไม่เปิดเผย Pairing keys, UDID หรือข้อมูลลูกค้า
4. ยืนยันความพร้อมใช้งานทีละเวอร์ชันและอุปกรณ์ ก่อนตั้งป้ายว่า Supported
